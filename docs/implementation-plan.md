# План реализации failover

**Цель:** реализовать [согласованный алгоритм](failover-design.md), структурировать Mihomo-конфиг и сохранить существующие команды и пути.

**Состояние:** дизайн подтверждён 15 октября 2026 года. Реализация выполнена в текущем каталоге; локальные проверки пройдены. На роутере не применялась.

**Подход:** изменить существующий Python-модуль без новых runtime-зависимостей. Проверять контроллер, замеры и cron через моки. Работать в текущем каталоге; worktree и копии проекта не создавать.

Для выполняющей модели: применять `superpowers:executing-plans` при самостоятельной реализации; делегирование — только при выборе пользователем соответствующего способа.

## Результат проверки

Все 50 unit-тестов проходят. Независимый обзор не выявил дефектов реализации. YAML разобран с поддержкой aliases; сравнение до/после подтвердило сохранность правил, провайдеров, DNS и существующих групп, кроме исправления неопределённого `Proxy` в `Global`.

Нативная проверка Mihomo недоступна: бинарник отсутствует. Обнаруженное прежнее несоответствие `MATCH,Other` и группы `other` оставлено без изменения правил; это ограничение не позволяет заявлять о полной валидности конфига для запуска Mihomo. Сборка IPK, live-проверка контроллера и применение на роутере не выполнялись.

Решения по ранее открытым деталям: время очистки хранится рядом с логом в `.cleanup`, первая проверка начинает отсчёт без удаления лога, ручная очистка сбрасывает отсчёт; все действия кроме справки используют общий lock. Прежние `fresh_top_n` и `close_result_percent` принимаются, но игнорируются.
