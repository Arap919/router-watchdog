# План разделения замера и выбора ноды MCP

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Цель:** сначала показать пользователю сравнение скоростей, затем отдельно переключить на выбранную им успешно измеренную ноду.

**Архитектура:** `find_faster_node()` теряет параметр `apply` и всегда вызывает существующий report-only CLI. Новый `select_measured_node(node)` принимает точное имя из последнего успешного сравнения этого MCP-процесса. MCP хранит список успешно измеренных нод и исходную выбранную ноду; отдельная фиксированная CLI-команда `--select-node` получает JSON через stdin, проверяет актуальную принадлежность, свежую доступность и неизменность исходного выбора под общим lock, затем переключает и проверяет результат. Перезапуск MCP требует нового сравнения.

**Технологии:** существующие Python, FastMCP 1.x, SSH, unittest.

**Согласованный дизайн:** обсуждение в текущем чате от 27.10.2026: замер → сравнительная таблица → выбор любой успешно измеренной ноды → отдельное переключение. Обычная работа watchdog остаётся прежней.

## Ограничения

- Не менять `choose_and_apply()`, cron и существующее поведение CLI `--find-faster --apply`.
- Не добавлять произвольных SSH-команд; имена нод передавать только в JSON stdin.
- Сохранить локальный флаг `XKEEN_ALLOW_APPLY=1` для переключения.
- После сравнения агент обязан показать все успешные результаты, текущую ноду, Mbps, задержку, разницу с baseline, время и неудачные замеры; затем дождаться выбора пользователя.
- Документация не обещает принудительное отображение таблицы любым MCP-клиентом: вывод обеспечивает агент по инструкции инструмента.
- Не публиковать и не развёртывать изменения в рамках этой задачи.

## Проверки рисков

- Имя с кавычками или shell-символами остаётся данными stdin.
- Нода вне последнего сравнения либо без успешного замера отклоняется до SSH.
- Неудачный повторный замер очищает прежний список выбора.
- Изменившийся текущий выбор, исчезнувшая или недоступная нода не перезаписываются молча.
- Выбор текущей ноды возвращает подтверждённый no-op; медленная успешно измеренная нода допускается.
